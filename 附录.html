    13.1. 安装 PHP

    示例和案例研究需要 [PHP] 8.4 或更高版本（[Symfony] 8 要求如此），以及扩展 [intl]（数字和日期格式化，示例 16，以及 ICU 消息，示例 22）、[pdo_mysql] （访问 [MySQL]，示例 28 和案例研究）、[mbstring]、和 [openssl]。它们已在 8.4 版本上测试过。

    在 [Windows] 下，最简单的是 [Laragon] （laragon.org），它会安装 [PHP]、[Composer]、一个 [MySQL] 服务器，以及 [HeidiSQL] 管理工具。如果所提供的 [PHP] 版本低于 8.4，请从 windows.php.net/download 下载更新的版本（Thread Safe 版本，压缩包 [.zip]），并将其解压到 [bin\php] 文件夹中，该文件夹位于 [Laragon] 内；然后可以通过 [Laragon] 中的 PHP / Version 菜单选择它。PHP / Extensions 菜单只需单击一下即可启用某个扩展（[intl]、[pdo_mysql]）。[Laragon] 终端（Terminal 按钮）支持命令 [php]、[composer]、和 [mysql]。

    如果不使用 [Laragon]，请将 [PHP] 的压缩包解压到一个文件夹（[C:\php]）中，将该文件夹添加到环境变量 [Path] 中，然后通过复制 [php.ini] 配置文件，即 [php.ini-development]，来创建它，并删除注释掉所需扩展那几行的分号：

    1
2
3
4
    extension=intl
extension=mbstring
extension=openssl
extension=pdo_mysql

    在 [macOS] 下，包管理器 [Homebrew] 可以安装 [PHP] 及其标准扩展：[brew install php]。对于 [Linux] （[Ubuntu]），发行版提供的版本通常较旧；[ppa:ondrej/php] 仓库提供最新版本：

    1
2
    sudo add-apt-repository ppa:ondrej/php
sudo apt install php8.4-cli php8.4-intl php8.4-mbstring php8.4-mysql php8.4-xml php8.4-curl php8.4-zip

    在新的控制台中验证安装：

    1
2
    php -v
php -m

    第一条命令应显示等于或高于 8.4 的版本号（例如 [PHP 8.4.12]）；第二条命令列出已加载的扩展，其中包括 [intl] 和 [pdo_mysql]。命令 [php --ini] 会指示正在使用哪个文件，即 [php.ini]。

    13.2. Composer

    [Composer] 是 [PHP] 的库管理器（getcomposer.org）。它由 [Laragon] 提供；对于 [Windows]，如果不使用 [Laragon]，则使用其安装程序（[Composer-Setup.exe]）；对于 [macOS]，使用 [brew install composer]；对于 [Linux]，请按照 getcomposer.org/download 页面上的说明操作。验证安装：

    1
    composer -V

    项目文件夹（包含 [composer.json] 的文件夹）中常用的命令：

    1
2
3
4
5
    composer install              # 安装项目的库（vendor 文件夹）
composer show                 # 已安装的库
composer update               # 升级到 composer.json 允许的最新版本
composer require name/package # 向项目添加一个库
composer dump-autoload        # 重建类加载器（在添加类文件夹之后）

    [Composer] 从 [Packagist] 仓库（packagist.org）下载库：安装期间需要连接互联网。如果你位于企业代理之后，请使用环境变量 [HTTP_PROXY] 和 [HTTPS_PROXY] 指定代理。[vendor] 文件夹不会从一台机器复制到另一台机器（它可能包含绝对路径，而且体积很大）；它通过 [composer install] 重新创建。这就是它不包含在课程材料中的原因。[examples] 文件夹有自己的 [vendor] 文件夹，由全部 28 个示例共享；案例研究则有它自己的 vendor 文件夹。

    案例研究使用 [Runtime] 组件，它来自 [Symfony]，同时也是 [Composer] 的[Composer]插件：正是该组件生成了 [vendor/autoload_runtime.php] 文件，由 [public/index.php] 读取。[Composer] 会请求运行插件的许可；应用程序的 [composer.json] 文件授予了该许可（[allow-plugins] 部分）。在 [Linux] 下，当由 [Composer] 会在由 [root] 账户启动时拒绝运行插件，除非将环境变量 [COMPOSER_ALLOW_SUPERUSER] 设置为 [1]：否则，文件 [autoload_runtime.php] 将会缺失（参见案例研究中的“常见问题”）。最好不要在 [root] 账户下工作。

    13.3. 安装 Visual Studio Code

    [Visual Studio Code] 可从 code.visualstudio.com 下载。添加三个扩展（View 菜单 / Extensions）：

    • PHP Intelephense：代码补全、代码导航（包括位于 [Symfony] 的 [vendor] 文件夹中的代码）以及错误报告；
    • Twig Language 2：[Twig] 视图（[.html.twig] 文件）的语法高亮和补全；
    • YAML （来自 [Red Hat]）：配置文件（[config/packages/*.yaml]）和字典（[translations/*.yaml]）的语法高亮和验证。

    PHP Debug 扩展允许你使用 [Xdebug] 调试器分步执行代码（它是 [PHP] 的扩展，需单独安装：xdebug.org）。

    打开 [examples] 文件夹或案例研究文件夹（File 菜单 / Open Folder）。内置终端（Terminal 菜单 / New Terminal）允许你在不离开编辑器的情况下启动应用程序并运行 [php bin/console ...] 命令。

    13.4. 使用 Laragon 安装 MySQL

    [Laragon] 安装开箱即用的 [MySQL] 服务器（适用于 [Windows]），并附带 [HeidiSQL] 管理工具。安装之后：

    • “Start All”按钮会在端口 3306 上启动 [MySQL] 服务器；
    • 用户 [root] 没有密码：这些就是示例 28 和案例研究的 [DATABASE_URL] 变量在 [.env] 文件中的值（[mysql://root:@127.0.0.1:3306/...]）；
    • Database 按钮会打开 [HeidiSQL]，其中 File 菜单 / Run File SQL 可运行脚本 [dbpersons.sql] （示例 28）和 [dbrdvmedecins2.sql] （案例研究）。

    在 [Linux] 或 [macOS] 中，使用系统的包管理器安装 [MySQL] 或 [MariaDB] ，并使用命令行客户端 [mysql] 运行脚本。[pdo_mysql] 驱动无需任何配置即可与两者配合使用。在 [Linux] 下，[root] 账户（对于 [MariaDB] ）通常被配置为只能通过系统账户 [root] 登录（[sudo mysql]）：此时需要为应用程序创建一个用户，并在它们的 [DATABASE_URL] 变量所在的 [.env] （[mysql://course:course@127.0.0.1:3306/...]）文件中指定它：

    1
    sudo mysql -e "CREATE USER 'course'@'localhost' IDENTIFIED BY 'course'; GRANT ALL ON *.* TO 'course'@'localhost';"

    对于 [MariaDB]，还需要在 [DATABASE_URL] 变量中指定其版本（例如 [serverVersion=10.11.2-MariaDB] 而不是 [serverVersion=8.0.32]）：[Doctrine] 会根据所使用的数据库调整它所写的 SQL。

    13.5. 安装 curl

    [curl] 已包含在 [Windows] 10 和 11、[macOS]、以及大多数 [Linux] 发行版中。在 [PowerShell] 中，必须键入 [curl.exe]，而不是 [curl]：在较旧版本的 [PowerShell] 中，[curl] 是另一个命令（[Invoke-WebRequest]）的别名，其选项不同。在 [Windows] 命令提示符（[cmd]）中，JSON 字符串的引号要写成 [\"] （示例 11），并且包含 [&] 的 URL 必须用双引号括起来。

    13.6. symfony 工具

    [Symfony] 提供了一个命令行工具，即 [symfony] 程序（Symfony CLI），学习本文档并不需要它，但文档中处处都会提到它。按照 symfony.com/download 页面上的说明安装：在 [Windows] 下，使用 [Scoop] （[scoop install symfony-cli]）包管理器；在 [macOS] 下，使用 [Homebrew] （[brew install symfony-cli/tap/symfony-cli]）；在 [Linux] 下，使用系统的包管理器。最有用的命令：

    1
2
3
4
    symfony check:requirements      # PHP 的配置适合 Symfony 吗？
symfony new my-project --webapp # 一个新的完整项目（见引言）
symfony server:start            # 一个开发服务器（http://127.0.0.1:8000）
symfony console debug:router    # 相当于 php bin/console debug:router

    它的开发服务器与 [php -S localhost:8000 -t public] 的作用相同，但有一些优势：它能自己找到 [public] 文件夹，能以 HTTPS 提供站点服务（在 [symfony server:ca:install] 之后），能在后台运行（[symfony server:start -d]，然后 [symfony server:stop]），并且在安装了多个版本时会选择项目所用的 [PHP] 版本。本文档所使用的 [PHP] 内置服务器，其优势是无需安装。
