    12. 结论

    本文档描述了使用 [Symfony] 框架开发一个 MVC Web 应用程序的过程：这是一个 HTML 页面由服务器使用 [Twig] 视图生成、没有浏览器端 [JavaScript] 框架的应用程序。它分步遵循了 [Laravel] 课程，而该课程本身又建立在 [Flask]、[Spring MVC]、[ASP.NET Core MVC] 和 [NestJS] 课程之上：从操作和路由到视图、表单、国际化、安全和数据访问，最后是一个综合案例研究。

    因此，同样的 28 个示例和同一个应用程序，使用六个框架编写：[TypeScript] 版、[C#] 版、[Java] 版、[Python] 版，以及两个 [PHP] 版。概念是相同的；只有名称和机制不同。[Laravel] 与 [Symfony]（[PHP] 世界的两大主要框架）之间的对应关系：

    关于 [Laravel]，需要注意的要点是：

    • [Symfony] 是一组独立的组件，组装成Bundle。每个组件都是自包含的，[Laravel] 使用了其中的几个（[HttpFoundation]、[HttpKernel]、[Routing]、[Console]……）：上一课的读者会在这里认出相同的对象：[Request] 和 [Response]。名为 [Symfony] 的应用程序只安装其所需的组件：示例一开始只有 [framework-bundle]，然后逐个添加 [Twig]、验证、表单、安全和 [Doctrine]；
    • 一切都通过服务容器 和 依赖注入进行：没有外观或全局函数，而是将服务传给构造函数并按类型声明（自动装配）。一个类的依赖在其构造函数中始终可见。容器会被编译 为 [PHP] 代码并缓存：这抵消了每次请求都重新构建应用程序的开销（示例 01）；
    • 请求的处理由一系列内核事件 组成，监听器对这些事件作出响应：语言、安全、应用程序控制（通行证）和错误页面都在这里处理。这一机制比 [Laravel] 中的中间件更明确：每个监听器选择自己的事件和优先级，命令 [debug:event-dispatcher] 会显示所有监听器的顺序；
    • 配置是显式的，位于 YAML（或 [PHP]）文件中，这些文件描述每个 Bundle：防火墙、访问规则、限制器和会话、[Doctrine]。命令 [debug:router]、[debug:container] 和 [debug:config] 会显示 [Symfony] 所解释的内容；
    • [PHP] 属性描述代码：路由（[#[Route]]）、约束（[#[Assert\NotBlank]]）、实体（[#[ORM\Column]]）、监听器（[#[AsEventListener]]）、权限（[#[IsGranted]]）和注入（[#[Autowire]]）。我们甚至自己编写了一些（[#[Timed]], [#[RegistrationPassRequired]]）；
    • 表单是对象，由类来描述，例如：字段、约束、值转换、输入重新显示、错误消息和防 CSRF 令牌。对于小型表单，这比 [Laravel] 中的表单请求代码更多，而对于大型表单则少得多：一个主题（[Bootstrap] 5）以相同的方式为所有字段设置样式；
    • 安全是一个功能完备的组件：防火墙、验证用户的身份验证器、访问规则、角色层级和投票器。我们使用一个只有几十行的身份验证器，使其适应了我们的需求（Cookie 中的 JWT 令牌），同时没有丢失任何其他功能：[access_control]、[#[IsGranted]]、视图中的 [is_granted] ；
    • [Doctrine] 遵循Data Mapper 模式：实体是普通的 [PHP] 对象，它们并不知道数据库的存在；由实体管理器 读取它们、跟踪其变化，并在 [flush] 时将它们在单个事务中一并写入。它比 [Eloquent] 的 Active Record 更抽象，清晰地将对象与其记录分离，并支持乐观锁等机制。与 [Eloquent] 一样，通过 SQL 命令日志可以验证发送给数据库的内容；
    • [Twig] 视图有自己的语言，它比 [PHP] 在 [Blade] 视图中的用法更有限：视图只能显示提供给它的数据。这既是约束，也是保证：逻辑保留在类中。它们被编译为 [PHP] 并缓存，并自动对其显示的内容进行转义。

    案例研究表明，没有必不可少的 [JavaScript] 的经典 HTML 应用程序，仍然是简单而稳健的解决方案：每个页面就是一个 URL，浏览器的“后退”按钮可以正常工作，并且服务器掌控一切。有限地使用 [JavaScript] （确认窗口）可以改善用户体验，而不是运行所必需的。[Symfony] 也可以支持交互性更强的应用程序，既可以不离开 [Twig] （[Symfony UX]：[Turbo]、[Stimulus]、Live Components），也可以配合浏览器端的 [JavaScript] 框架，为其提供 JSON API（[API Platform]）：这将在其他文档中介绍。

    如需进一步了解，请参阅 [Symfony] 文档（symfony.com/doc），特别是专门介绍服务容器、内核事件、表单、安全和 [Doctrine] 的页面，以及 [Twig] 的文档（twig.symfony.com）、[Doctrine] 的文档（doctrine-project.org）、[PHP] 的文档（php.net/manual/en），并将本应用程序与其对应版本 [Laravel]、[Flask]、[Spring MVC]、[ASP.NET Core MVC]、和 [NestJS] 进行比较。
