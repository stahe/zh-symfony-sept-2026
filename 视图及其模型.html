    4. 视图及其模型

    到目前为止，动作都是自己生成响应：文本、JSON，以及写成字符串的少量 HTML 标签。在 MVC 应用程序中，这是视图的职责：一个描述页面 HTML 的文件，其中带有占位符，用于放置动作传给它的数据——即视图的模型。

    [Symfony] 使用同一团队创建的 [Twig] 视图引擎。[Twig] 视图是一个文件，其名称以 [.html.twig] 结尾（输出格式，后跟引擎），存放在应用程序的 [templates] 文件夹中。它是一个文本文件——这里是 HTML——其中有三类标签会在服务器端被解释：

    • [{{ expression }}]：表达式的值，插入到页面中；
    • [{% instruction %}]：一条指令 （标签）；条件（[{% if %}]）；循环（[{% for %}]）、模板继承（[{% extends %}]、[{% block %}]）、包含（[{% include %}]）等；
    • [{# comment #}]：注释，不会出现在生成的页面中。

    其余内容原样复制。表达式不是用 [PHP] 编写的，而是用 [Twig] 的语言，它更简单也更安全：[model.title] 指的是对象 [model] 的属性 [title]（或其方法 [getTitle()]，或数组的键 [title] ：[Twig] 会自行查找）；过滤器 转换一个值（[name|upper] 将姓名转为大写）；函数 执行计算（[path('home')] 生成一个 URL）。[Twig] 因此类似于 [Jinja2] （[Flask]）——它从中汲取了灵感——或 [Django] 的引擎；它不同于 [Blade] （[Laravel]）和 [Razor] （[ASP.NET Core]），后两者把 HTML 与宿主语言的代码混合在一起。[Twig] 视图不能执行任意的 [PHP] 代码：它只能显示传给它的数据。这是有意为之的设计：应用程序逻辑保留在各个类中。视图并不是每次请求都被解释：首次使用时，[Twig] 会将其编译为一个 [PHP] 类，存放在 [var/cache/dev/twig] 文件夹中，只要视图不变就会重复使用它。我们稍后会看到这个文件是什么样子。

    <?php
// src/Controller/ViewsController.php：返回视图的操作

namespace App\Controller;

use App\Model\PageModel;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

#[Route(methods: ['GET'])]
class ViewsController extends AbstractController
{
    // render：Twig 引擎根据视图模板
    // templates/views/index.html.twig 以及数组中传递的变量（这里
    // 只有一个，[model]）构建页面；生成的页面就是响应的主体
    #[Route('/', name: 'index')]
    public function index(): Response
    {
        $model = new PageModel(
            'My first view',
            'This page was built by Twig, on the server.',
            date('H:i:s'));
        return $this->render('views/index.html.twig', ['model' => $model]);
    }

    // 同一个视图配合另一个模型；或者另一个视图，使用 404 状态码
    #[Route('/hello/{name}', name: 'hello')]
    public function hello(string $name): Response
    {
        if ($name === 'unknown') {
            // render 的第三个参数：要补全的响应，这里设置了 404 状态码
            return $this->render('views/unknown.html.twig', ['name' => $name],
                new Response(status: Response::HTTP_NOT_FOUND));
        }
        $model = new PageModel(
            "Hello $name",
            'This time, the title of the page comes from the URL.',
            date('H:i:s'));
        return $this->render('views/index.html.twig', ['model' => $model]);
    }
}
    • 第 20–23 行：动作构建视图模型。[date] 函数，源自 [PHP]，用于格式化当前时间：[H] 格式化小时，[i] 格式化分钟，[s] 格式化秒；
    • 第 24 行：[render] 方法（来自 [AbstractController] ）指示 [Twig] 生成页面。第一个参数是视图的名称：即相对于 [templates] 文件夹的文件路径。第二个参数是一个关联数组，其中每个键都会成为视图中的一个变量——这里只有一个：[model]。[render] 返回一个 [Response] 对象，其主体是生成的页面（类型为 [text/html]）；
    • 第 31–35 行：另一个视图，带有另一个变量（[name]）。[render] 的第三个参数是一个待填充的响应：这里是用于自定义错误页面的 404 响应。[new Response(status: ...)] 通过命名参数传递状态码，而其他参数保持默认值；
    • 第 36–40 行：与 [index] 动作相同的视图，但使用不同的模型。这就是把动作与视图分离的好处：同一个视图可以被多个动作使用。

    • 第 17–18 行：[{{ }}] 会转义 HTML（2a）；而过滤器 [raw]则按原样插入值，不进行转义（2b）。[raw] 仅用于应用程序自己生成的 HTML，绝不用于用户输入；

    • 第 28–34 行：循环 [{% for ... in ... %}] …… [{% endfor %}]。在循环内部，特殊变量 [loop] 描述循环的状态：[loop.index0] （迭代序号，从 0 开始）、[loop.index] （从 1 开始）、[loop.first]、[loop.last] （在第一次和最后一次迭代时为 true）、[loop.length] （元素数量）。循环之外的变量（[model.name]）仍然可以访问；

    • 第 38 行：[for] 循环可以带有一个 [{% else %}] 块，在列表为空时执行。这比用 [{% if %}] 检查列表长度更简单；

// common/BootstrapController.php：一个提供 Bootstrap 文件的控制器，
// 由示例 15 到 28 共享（examples/common/bootstrap 文件夹），位于
// /bootstrap/... URL 下。这些示例中的每一个都在其
// config/services.yaml 文件中声明它

namespace Common;

use Symfony\Component\HttpFoundation\BinaryFileResponse;
use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;
use Symfony\Component\Routing\Attribute\Route;
use Symfony\Component\Routing\Requirement\Requirement;

class BootstrapController
{
    #[Route('/bootstrap/{file}', name: 'bootstrap', requirements: ['file' => Requirement::CATCH_ALL],
        methods: ['GET'])]
    public function serve(string $file): BinaryFileResponse
    {
        $folder = realpath(__DIR__.'/bootstrap');
        // realpath：所请求文件的绝对路径，不含 . 和 ..；
        // 如果文件不存在则为 false
        $path = realpath($folder.'/'.$file);
        // 一个存在的文件，并且确实位于该文件夹内（没有用 ../ 跳出该文件夹）
        if ($path === false || ! str_starts_with($path, $folder.DIRECTORY_SEPARATOR) || ! is_file($path)) {
            throw new NotFoundHttpException("unknown file: $file");
        }
        // 一个发送文件内容的响应；其类型根据扩展名确定
        $response = new BinaryFileResponse($path);
        $types = ['css' => 'text/css', 'js' => 'text/javascript', 'map' => 'application/json'];
        $response->headers->set('Content-Type', $types[pathinfo($path, PATHINFO_EXTENSION)] ?? 'application/octet-stream');
        return $response;
    }
}
    • 第 7 行：该类位于 [Common] 命名空间中，文件 [examples/composer.json] 将它与文件夹 [examples/common] 关联起来（参见引言）：因此 [Composer] 的类加载器无论在哪个示例中都能找到它；
    • 第 16–17 行：一个路由，其参数 [{file}] 接受任何路径结尾，包括斜杠（示例 02）：URL [/bootstrap/css/bootstrap.min.css] 指向文件夹中的 [css/bootstrap.min.css] 文件。该路由名为 [bootstrap]；
    • 第 20–27 行：提供由 URL 指定的文件需要谨慎：诸如 [/bootstrap/..%2F..%2F15-layout%2F.env] （其中 [/] 被编码为 [%2F]）的 URL 绝不能允许访问文件夹之外的文件。[realpath] 函数（属于 [PHP] ）计算文件的绝对路径，去除其中的 [.] 和 [..] 部分，如果文件不存在则返回 [false] 。我们验证所得路径是否以文件夹路径开头（[str_starts_with]），并且它指向一个文件（[is_file]）；否则返回 404 错误。[DIRECTORY_SEPARATOR] 是系统的路径分隔符：在 [\] 下为 [Windows]，其他系统下为 [/] ；
    • 第 29–32 行：[BinaryFileResponse] 对象是发送文件内容的响应。内容类型根据文件扩展名确定（由 [pathinfo] 提供），从而使样式表被正确声明为 [text/css]：浏览器会拒绝被声明为其他类型的样式表。

    <?php
// src/Twig/FormatsExtension.php：一个 Twig 扩展（EXTENSION），为视图语言
// 添加两个过滤器：money 和 long_date

namespace App\Twig;

use DateTimeInterface;
use IntlDateFormatter;
use NumberFormatter;
use Symfony\Component\HttpFoundation\RequestStack;
use Twig\Extension\AbstractExtension;
use Twig\TwigFilter;

class FormatsExtension extends AbstractExtension
{
    // 请求栈，用于获知当前请求的语言
    public function __construct(private RequestStack $requests)
    {
    }

    // 扩展的过滤器：它们在视图中的名称，以及实现它们的方法
    public function getFilters(): array
    {
        return [
            new TwigFilter('money', $this->money(...)),
            new TwigFilter('long_date', $this->longDate(...)),
        ];
    }

    // 以某种货币表示的金额（以分为单位），采用请求语言的格式：
    // 114990 -> 英语为 "€1,149.90"，法语为 "1 149,90 €"。
    // PHP 的 intl 扩展了解每个国家的惯例
    public function money(int $cents, string $currency = 'EUR'): string
    {
        $formatter = new NumberFormatter($this->language(), NumberFormatter::CURRENCY);
        return $formatter->formatCurrency($cents / 100, $currency);
    }

    // 用完整单词表示的日期，使用请求的语言："Sunday, September 27, 2026"
    public function longDate(DateTimeInterface $day): string
    {
        $formatter = new IntlDateFormatter($this->language(), IntlDateFormatter::FULL, IntlDateFormatter::NONE);
        return $formatter->format($day);
    }

    private function language(): string
    {
        return $this->requests->getCurrentRequest()?->getLocale() ?? 'en';
    }
}
    • 第 14 行：[Twig] 的扩展继承自 [AbstractExtension] 类。它是一个服务，与 [src] 文件夹中的每个类一样；[Symfony] 会把它识别为扩展（[autoconfigure]）并传递给 [Twig]；
    • 第 17–19 行：扩展需要当前请求的语言。它接收请求栈 （[RequestStack]），这是 [Symfony] 中知道当前请求的服务（之所以有栈，是因为一个请求可能在内部触发另一个请求）；
    • 第 22–28 行：方法 [getFilters] 返回扩展的过滤器：对每个过滤器，给出它在视图中的名称和实现它的函数。[$this->money(...)] （带省略号）并不调用该方法：它把方法变成一个值——一个可以稍后调用的函数（一等可调用对象）。扩展还可以提供函数（[getFunctions]）和测试（[getTests]）；
    • 第 33–37 行：格式化以分为单位接收的金额（参见示例 06）。这取决于语言：法语中为 [1 149,90 €] （空格分隔千位，小数点用逗号，符号在金额之后）；英语中为 [€1,149.90]。[NumberFormatter] 类，属于 [intl] 扩展（来自 [PHP]），支持所有国家的习惯（它使用 Unicode 项目 CLDR 的数据）：它针对一种语言和一种样式创建（这里是 [CURRENCY]，用于金额），而 [formatCurrency] 格式化金额，货币由其国际代码指定（[EUR]、[USD]）。过滤器的第一个参数是被过滤的值；其后的参数是它在视图中的属性（[priceCents|money('USD')]）；

// src/EventListener/SetLanguage.php：每个请求的语言

namespace App\EventListener;

use Symfony\Component\EventDispatcher\Attribute\AsEventListener;
use Symfony\Component\HttpKernel\Event\RequestEvent;
use Symfony\Component\HttpKernel\KernelEvents;

// priority：同一事件的监听器的顺序（数值最大的最先）；
// 20：在路由（32）之后，在使用语言的 Symfony 监听器（16、15）之前
#[AsEventListener(event: KernelEvents::REQUEST, priority: 20)]
class SetLanguage
{
    // URL 的 ?lang=fr 参数，否则为英语
    public function __invoke(RequestEvent $event): void
    {
        $request = $event->getRequest();
        $request->setLocale($request->query->get('lang') === 'fr' ? 'fr' : 'en');
    }
}

    每个请求都有一种语言 （区域设置），默认为配置中指定的语言 [default_locale] （如果未配置任何内容，则为 [en] ）。这里，URL 参数 [?lang=fr] 选择法语；英语是默认语言。 一个针对 [kernel.request] 事件的监听器（示例 12）在每个动作之前使用请求的 [setLocale] 方法来设置它。属性的 [priority] 参数设定同一事件的各监听器的顺序：优先级最高的最先处理（默认为 0）。[Symfony] 自身有若干 [kernel.request] 的监听器：路由（优先级 32），其后是准备与语言相关的服务的监听器（16 和 15）。我们的监听器必须在这两者之间运行：20。命令 [php bin/console debug:event-dispatcher kernel.request] 按顺序显示该事件的所有监听器。以这种方式设置的语言只适用于当前请求：下一个请求将恢复为默认语言。国际化一章将使用这同一种语言来翻译文本。

    {
        return [
            new Book('Le Rouge et le Noir', 'Stendhal', 'novel'),
            new Book('Les Fleurs du mal', 'Baudelaire', 'poetry'),
            new Book('Madame Bovary', 'Flaubert', 'novel'),

    #[Route('/', name: 'books_home', methods: ['GET'])]

    public function search(Request $request): Response
    {
        // getString：以字符串形式表示的参数（缺失时为 ''）

use App\Service\ListsService;
use Symfony\Component\Form\AbstractType;
use Symfony\Component\Form\Extension\Core\Type\ChoiceType;
use Symfony\Component\Form\Extension\Core\Type\DateType;
use Symfony\Component\Form\Extension\Core\Type\HiddenType;
use Symfony\Component\Form\Extension\Core\Type\PasswordType;
use Symfony\Component\Form\Extension\Core\Type\TextareaType;
use Symfony\Component\Form\Extension\Core\Type\TextType;
use Symfony\Component\Form\FormBuilderInterface;
use Symfony\Component\Validator\Constraints\NotBlank;

class FieldsType extends AbstractType
{
    // 表单类型是一个服务：它接收列表服务
    public function __construct(private ListsService $lists)
    {
    }

    // 表单的字段，按其显示顺序排列
    public function buildForm(FormBuilderInterface $builder, array $options): void
    {
        $builder
            // 单选按钮：一个选项列表（ChoiceType），“expanded”；
            // constraints：该字段的验证约束（见示例 08）
            ->add('title', ChoiceType::class, [
                'choices' => $this->lists->titles(),
                'expanded' => true,
                'label_attr' => ['class' => 'radio-inline'],
                'constraints' => [new NotBlank(message: 'The title is required.')],
            ])
            // 一个输入字段；required => false：该字段不是必填的
            ->add('name', TextType::class, ['required' => false])
            // 密码：绝不会在页面中再次显示
            ->add('password', PasswordType::class, ['label' => 'Password', 'required' => false])
            // 日期：一个 <input type="date"> 字段；其值是 yyyy-mm-dd 字符串
            ->add('birth_date', DateType::class, [
                'label' => 'Date of birth',
                'widget' => 'single_text',
                'input' => 'string',
                'required' => false,
            ])
            // 复选框：一个展开的选项列表，可多选
            ->add('hobbies', ChoiceType::class, [
                'choices' => $this->lists->hobbies(),
                'expanded' => true,
                'multiple' => true,
                'label_attr' => ['class' => 'checkbox-inline'],
                'required' => false,
            ])
            // 下拉列表：一个未展开的选项列表
            ->add('country', ChoiceType::class, ['choices' => $this->lists->countries()])
            // 多选列表，显示为四行
            ->add('languages', ChoiceType::class, [
                'label' => 'Spoken languages',
                'choices' => $this->lists->languages(),
                'multiple' => true,
                'attr' => ['size' => 4],
                'required' => false,
            ])
            ->add('comment', TextareaType::class, ['required' => false, 'attr' => ['rows' => 2]])
            // 一个隐藏字段
            ->add('token', HiddenType::class);

// src/Controller/FormController.php：一个使用所有字段类型的表单

namespace App\Controller;

use App\Form\FieldsType;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

class FormController extends AbstractController
{
    // GET：带初始值的表单；POST：读取发送的字段，
    // 进行验证，然后由同一个表单再次显示
    #[Route('/form', name: 'form', methods: ['GET', 'POST'])]
    public function form(Request $request): Response
    {
        // 初始值（每个字段一个，多值字段则为数组）
        $initial = ['title' => 'Mme', 'country' => 'fr', 'languages' => ['French'], 'token' => 'A7X2'];
        // createForm：根据其描述构建的表单
        $form = $this->createForm(FieldsType::class, $initial);
        // handleRequest：如果请求是 POST，则将收到的字段复制
        // 到表单中，然后进行验证
        $form->handleRequest($request);
        $model = ['form' => $form];
        if ($form->isSubmitted()) {
            // 浏览器实际发送的内容，逐个字段
            $received = [];
            foreach ($request->request->all() as $name => $value) {
                foreach ((array) $value as $key => $v) {
                    $received[] = "{$name}[$key] = [".implode(', ', (array) $v).']';
                }
            }
            $model += [
                'received' => implode("\n", $received),
                'valid' => $form->isValid(),
                // getErrors(true)：所有字段的错误
                'errors' => $form->getErrors(true),
                // getData()：表单的值，由每个字段进行转换
                'data' => $form->getData(),
            ];
        }
        return $this->render('form/form.html.twig', $model);
    }
}
    • 第 16 行：一个动作同时处理两种方法：GET 显示表单，POST 处理表单。这是使用 [Symfony] 编写表单动作的标准方式；
    • 第 20 行：表单的初始值：一个关联数组，每个字段对应一个值（多值字段对应一个数组）；
    • 第 22 行：[createForm] 根据表单类型和初始数据创建表单——一个 [Form] 对象；
    • 第 25 行：[handleRequest] 检查请求。对于 GET，它什么也不做。对于包含表单字段的 POST，它把这些字段复制到表单中：每个字段转换自己的值（日期、列表等），验证所选内容是否在提供的选项之中，然后表单再验证约束和防 CSRF 令牌；

namespace App\Form;

use App\Model\Registration;
use Symfony\Component\Form\AbstractType;
use Symfony\Component\Form\Extension\Core\Type\EmailType;
use Symfony\Component\Form\Extension\Core\Type\IntegerType;
use Symfony\Component\Form\Extension\Core\Type\PasswordType;
use Symfony\Component\Form\Extension\Core\Type\RepeatedType;
use Symfony\Component\Form\Extension\Core\Type\TextType;
use Symfony\Component\Form\FormBuilderInterface;
use Symfony\Component\OptionsResolver\OptionsResolver;

class RegistrationType extends AbstractType
{
    public function buildForm(FormBuilderInterface $builder, array $options): void
    {
        $builder
            // attr：输入字段上额外的 HTML 属性（用于
            // 浏览器验证，见后文）
            ->add('name', TextType::class, ['attr' => ['maxlength' => 20]])
            ->add('email', EmailType::class, ['label' => 'Email address'])
            // IntegerType：整数；不是整数的输入会产生
            // invalid_message 错误
            ->add('age', IntegerType::class, [
                'label' => 'Age',
                'attr' => ['min' => 18, 'max' => 120],
                'invalid_message' => 'An integer is expected.',
            ])
            // RepeatedType：两个必须接收相同值的字段（密码
            // 及其确认）；数据中只有一个值
            ->add('password', RepeatedType::class, [
                'type' => PasswordType::class,
                'first_options' => ['label' => 'Password', 'attr' => ['minlength' => 6]],
                'second_options' => ['label' => 'Confirmation'],
                'invalid_message' => 'The confirmation does not match the password.',
            ]);
    }

    // 表单的选项：其数据是一个 Registration 对象
    public function configureOptions(OptionsResolver $options): void
    {
        $options->setDefaults(['data_class' => Registration::class]);
    }
}

    4.8. 示例 20：Post/Redirect/Get 模式

    当 POST 动作以页面作为响应时，该页面是 POST 的结果。如果用户重新加载页面（按 [F5]），浏览器会重新发送 POST 请求，并在此之前显示一条很少有人阅读的警告：命令被发送了两次，消息也被发布了两次。Post/Redirect/Get 模式（PRG）可以避免这个问题：成功的 POST 动作不返回页面；它以重定向 （示例 04）到一个 GET 页面作为响应，浏览器会立即请求该页面。重新加载这个页面只是重新执行 GET 动作。

    还剩一个问题：GET 页面想要显示一条消息（“任务已添加”），但知道这条消息的是 POST 动作，而它无法向尚未发生的请求传递变量。解决方案是：闪现消息，由 POST 动作放入会话 中，保留到被读取为止，显示一次后即被丢弃。

// src/Service/TasksService.php：任务列表，由所有
// 用户共享。在 PHP 中，对象不会在请求之后保留：该列表
// 存储在应用程序的缓存中（这里是 var/cache/dev/pools 文件夹中的一个文件）

namespace App\Service;

use Psr\Cache\CacheItemPoolInterface;
use Symfony\Component\Lock\LockFactory;

class TasksService
{
    private const KEY = 'tasks';

    // 应用程序的缓存（cache.app 服务）和锁工厂
    public function __construct(
        private CacheItemPoolInterface $cache,
        private LockFactory $locks,
    ) {
    }

    /** @return list<string> */
    public function list(): array
    {
        // 存储在 [tasks] 键下的缓存项；isHit：它存在
        $item = $this->cache->getItem(self::KEY);
        return $item->isHit() ? $item->get() : ['Read chapter 3'];
    }

    public function add(string $label): void
    {
        // 多个请求可能同时运行（服务器用多个进程
        // 处理它们）：锁保证同一时间只有一个请求
        // 读取、修改并重写该列表
        $lock = $this->locks->createLock('tasks');
        // acquire(true)：等待锁空闲，然后获取它
        $lock->acquire(true);
        try {
            $tasks = $this->list();
            $tasks[] = $label;
            // 缓存项接收其新值，没有任何时间限制
            $item = $this->cache->getItem(self::KEY);
            $this->cache->save($item->set($tasks));
        } finally {
            // finally：无论如何都会释放锁，即使在异常之后也是如此
            $lock->release();
        }
    }
}

    任务列表由所有用户共享，并且必须在一个请求到下一个请求之间持久保存。在 [Java]、[C#]或 [Python] 中，它会保存在单个服务的内存中。在 [PHP] 中这是不可能的：正如我们在示例 01 和 06 中看到的，没有任何东西能在请求结束后留存。因此，列表必须存储在 [PHP] 之外：数据库、文件……或者应用程序缓存中，这里我们使用的就是缓存。

    • 第 16–20 行：该服务从 [Symfony] 接收两个服务。第一个是应用程序缓存 （来自 Cache 组件的 [cache.app] 服务），一个键值对存储，由标准化接口 [CacheItemPoolInterface] （PSR-6 标准）表示。默认情况下，它把值存储在 [var/cache/dev/pools] 文件夹的文件中；在生产环境中，更倾向于使用专用服务器，例如 [Redis] （只需一行配置）。第二个是 Lock 组件的锁工厂 ；
    • 第 23–28 行：[getItem] 检索存储在某个键下的缓存项；[isHit] 检查它是否存在，[get] 返回它的值。可以存储任何值（这里是字符串数组）：[Symfony] 会对其进行序列化——也就是说，使用 [serialize] 函数（来自 [PHP]）将其转换为文本；
    • 第 35–47 行：开发服务器与生产服务器一样，可以跨多个进程同时处理多个请求（环境变量 [PHP_CLI_SERVER_WORKERS] 设置 [php -S] 的进程数）。两个同时进行的添加操作可能读取到同一个列表，各自向其中添加自己的任务，然后再写回：第二次写入会覆盖第一个任务。锁 确保同一时刻只有一个请求执行它所保护的代码：[createLock('tasks')] 创建一个命名锁；[acquire(true)] 等待它变为可用，然后获取它；[release()] 释放它。这里，锁是 [var/lock] 文件夹中的一个文件，由操作系统锁定（[flock] 函数）；此外，多个服务器可以共享存储在 [Redis] 或数据库中的锁；

    • 第 42–43 行：缓存元素获得新值（[set]），然后被保存（[save]）。如果不指定生存期，它将被无限期保留（[expiresAfter(3600)] 会把它保留一小时）。

// src/Service/ContactsService.php：联系人，由所有人共享，存储在
// 应用程序的缓存中（见示例 20）

namespace App\Service;

use App\Model\Contact;
use Psr\Cache\CacheItemPoolInterface;
use Symfony\Component\Lock\LockFactory;

class ContactsService
{
    private const KEY = 'contacts';

    public function __construct(
        private CacheItemPoolInterface $cache,
        private LockFactory $locks,
    ) {
    }

    /** @return array{contacts: list<Contact>, lastId: int} */
    private function data(): array
    {
        $item = $this->cache->getItem(self::KEY);
        return $item->isHit() ? $item->get() : [
            'contacts' => [
                new Contact(1, 'Marie Durand', '01 23 45 67 89'),
                new Contact(2, 'Paul Martin', '06 12 34 56 78'),
                new Contact(3, 'Philippe Jandot', '02 98 76 54 32'),
            ],
            'lastId' => 3,
        ];
    }

    // 在锁定状态下修改数据：函数接收数据，
    // 对其进行修改（&），并返回操作的结果
    private function editData(callable $operation): mixed
    {
        $lock = $this->locks->createLock('contacts');
        $lock->acquire(true);
        try {
            $data = $this->data();
            $result = $operation($data);
            $this->cache->save($this->cache->getItem(self::KEY)->set($data));
            return $result;
        } finally {
            $lock->release();
        }
    }

    /** @return list<Contact> */
    public function list(): array
    {
        return $this->data()['contacts'];
    }

    // 联系人，如果不存在则为 null
    public function read(int $id): ?Contact
    {
        return array_find($this->list(), fn (Contact $c) => $c->id === $id);
    }

    public function edit(int $id, string $name, string $phone): ?Contact
    {
        return $this->editData(function (array &$data) use ($id, $name, $phone) {
            foreach ($data['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                    // 联系人是不可变的（readonly）：我们构建一个新的联系人，
                    // 用它替换数组中的旧联系人
                    return $data['contacts'][$i] = new Contact($id, $name, $phone);
                }
            }
            return null;
        });
    }

    public function add(string $name, string $phone): Contact
    {
        return $this->editData(function (array &$data) use ($name, $phone) {
            $contact = new Contact(++$data['lastId'], $name, $phone);
            $data['contacts'][] = $contact;
            return $contact;
        });
    }

    public function delete(int $id): ?Contact
    {
        return $this->editData(function (array &$data) use ($id) {
            foreach ($data['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                    // array_splice 从数组中删除第 i 项，并对后面的项重新编号
                    array_splice($data['contacts'], $i, 1);
                    return $contact;
                }
            }
            return null;
        });
    }
}

    联系人存储在缓存中，就像示例 20 中的任务一样。每个联系人是一个不可变的 [Contact] 对象（ID、姓名、电话号码），存储在一个数组中，并带有最近分配的 ID。关于 [PHP] 的几点说明：

    • 第 37–49 行：所有修改都遵循相同的模式：获取锁、读取数据、修改数据、写回数据、释放锁。此方法只对数组写入一次；每次修改都向它传递一个函数（类型为 [callable]，“可调用”），该函数接收数据并修改它。该函数必须修改数组本身，而不是副本：其参数声明为 [array &$data]，其中 [&] 表示按引用传递 （没有 [&] 时，数组会被复制；参见示例 06）。匿名函数中的关键字 [use] 使其可以访问外层函数中的变量（第 65 行：[$id], [$name], [$phone]）；
    • 第 44 行：调用依次进行：[getItem] 返回该元素，[set] 为其赋值并返回元素本身，[save] 存储它；
    • 第 63–75 行：联系人是不可变的：会创建一个新联系人，替换数组中的旧联系人。赋值是一个表达式，其值就是被赋的值：[return $data['contacts'][$i] = new Contact(...)] 替换联系人并返回它；
    • 第 80 行：放在变量前面的 [++] 使变量加 1 并返回新值；
    • 第 92 行：[array_splice] 从数组中移除一个元素，并对后面的元素重新编号；
    • 对于不存在的联系人，这些方法返回 [null] ：由控制器决定如何响应。

  });
})();
    • 第 3 行：代码被包含在一个匿名函数中，该函数立即执行；它的变量不会与页面上其他脚本的变量相互干扰；
    • 第 4–6 行：窗口、消息位置，以及等待确认的表单；
    • 第 9–17 行：对于每个带有 [data-confirmation] 属性的表单，拦截 [submit] 事件——表单提交时触发。[preventDefault()] 暂停提交；表单被搁置，其消息（[dataset.confirmation]，即 [data-confirmation] 属性的值）显示在窗口中，窗口随之出现；
    • 第 20–28 行：窗口中点击事件的单一处理程序：[event.target] 是被点击的元素；其属性 [data-action] 指明是哪个按钮。“是”使用 [submit()] 方法提交待处理的表单，与点击按钮不同，该方法不会触发 [submit] 事件（否则窗口会再次出现）；“否”则隐藏窗口。

    没有 [JavaScript] 时，表单会不经确认直接提交：页面仍然可用。这就是渐进增强：[JavaScript] 增加便利，但应用程序并不依赖它。
